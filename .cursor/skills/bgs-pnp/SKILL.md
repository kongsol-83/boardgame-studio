# 프린트 앤 플레이 출력

`projects/<slug>/pnp/<slug>-<날짜>.pdf` 를 만든다. **아트 없이도 나온다.**

룰이 흔들리는 동안 카드 아트를 뽑으면 카드가 바뀔 때마다 다시 뽑아야 한다. 도형과
텍스트만으로 먼저 인쇄해서 플레이테스트를 돌리고, 룰이 굳은 뒤에 아트를 얹는다.

## 진행

```bash
node tools/spec.mjs validate <slug>   # 1. 규격과 수량부터
node tools/pnp.mjs <slug> --check     # 2. 텍스트가 카드에 들어가는가
node tools/pnp.mjs <slug>             # 3. 렌더
```

### 1. 규격 검증

`validate` 가 통과해야 한다. `spec.json` 의 `count` 와 CSV 실제 수량이 어긋난 채로
인쇄하면 장수가 안 맞는다.

### 2. 텍스트 오버플로 검사

**렌더보다 먼저 돌린다.** `--check` 는 PDF를 만들지 않고 카드에 텍스트가 들어가는지만
본다. 넘치는 카드가 있으면 id와 함께 나온다.

넘치면 두 가지 중 하나다. 문구를 줄이거나 카드를 키운다. **문구를 줄이는 쪽을 먼저
검토한다.** 카드 텍스트가 길다는 건 대개 규칙이 복잡하다는 신호고, 카드를 키우면
인쇄 장수가 늘고 슬리브 호환이 깨진다.

인쇄한 뒤에 발견하면 룰을 다시 써야 하므로 여기서 잡는 게 훨씬 싸다.

### 3. 렌더

출력 결과를 사용자에게 알린다. 컴포넌트별 페이지 수와 총 장수를 말해준다.

## 인쇄할 때 전달할 것

PDF를 만든 뒤 이걸 안내한다. 이 설정이 어긋나면 재단선이 안 맞는다.

- **배율을 100%로 둔다.** "페이지에 맞춤"이나 "축소하여 인쇄"를 끄지 않으면 카드가
  작아져서 슬리브에 안 맞는다. 이게 가장 흔한 실수다
- **용지는 A4**, 방향은 자동. PDF 안에 세로와 가로 페이지가 섞여 있다
- **양면 인쇄는 긴 쪽 넘김(long edge)** 으로 한다. 뒷면은 용지 중심 기준으로 좌우를
  뒤집어 배치했으므로 긴 쪽 넘김이어야 앞뒤가 맞는다

## 글자 크기

포커 카드(63.5mm) 기준으로 이렇게 잡히고, 카드 폭에 비례해 조정된다.

| 요소 | 63.5mm 카드 | 하한 |
| --- | --- | --- |
| 제목 | 12pt | 8pt |
| 수치 | 9.5pt | 7.5pt |
| 본문 | 8.5pt | 7pt |
| ID | 5.5pt | 4.5pt |

**본문 하한이 7pt인 데는 이유가 있다.** 보드게임 카드 본문은 8pt가 실질적 하한이고 그
아래로는 인쇄물에서 읽히지 않는다. 그래서 카드가 작다고 무한정 줄이지 않는다. 텍스트가
안 들어가면 글자를 줄이는 게 아니라 **문구를 줄이거나 카드를 키우는 것**이 답이고,
`--check` 가 그걸 잡아준다.

**수치를 본문보다 크게 둔다.** 코스트와 파워는 한눈에 읽혀야 하는 정보다.

전체를 키우거나 줄이려면 `spec.json` 에 배율을 넣는다. 하한과 상한은 그대로 적용된다.

```json
"print": { "font_scale": 1.15 }
```

## 뒷면

`spec.json` 의 컴포넌트마다 `back` 을 정한다.

- `none` — 뒷면 없음. **프로토타입은 대개 이걸로 충분하다.** 슬리브에 넣고 뒤에 아무
  종이나 대면 카드 뒷면이 된다. 인쇄 장수가 절반이다
- `shared` — 공통 뒷면. 앞면 다음에 뒤집힌 페이지가 따라온다. `art/<comp-id>-back.png`
  가 있으면 쓰고, 없으면 회색 면으로 채운다
- `per-card` — 카드마다 다른 뒷면. 정렬 난이도가 확 올라가니 정말 필요할 때만

## 시트보다 큰 컴포넌트

보드처럼 A4를 넘으면 여러 장에 나눠 찍는다. 페이지 방향을 양쪽 다 계산해서 장수가 적은
쪽을 고른다. 420x297mm 보드는 가로로 깔면 4장, 세로로 깔면 6장이라 가로를 고른다.

각 조각에는 **정렬 마크와 조각 번호(`3/4 (2행 1열)`)** 가 찍힌다. 이어 붙일 때 어느
장이 어디인지 헷갈리지 않게 하려는 것이다.

아트가 있으면 통짜 이미지를 조각 경계에서 잘라 배치하므로 이음새에서 그림이 이어진다.

## 폰트

한글을 쓰면 시스템에서 CJK 폰트를 찾아 PDF에 임베드한다. Windows는 맑은 고딕, macOS는
AppleGothic, Linux는 나눔고딕이나 Noto를 찾는다. 쓰인 글자만 서브셋되므로 PDF는 작다.

못 찾으면 무엇을 설치하라고 알려주고 멈춘다. 직접 지정하려면 `spec.json` 에
`"print": { "font": "경로" }` 를 넣는다.

## 다음

인쇄해서 잘라보고 플레이테스트를 돌린다. 결과는 `/bgs-review` 로 기록한다.

룰이 굳으면 `/bgs-art` 로 아트를 얹고 다시 렌더한다.

## 주의

**실물로 확인하기 전에 다 됐다고 하지 않는다.** 여백, 재단선, 텍스트 크기, 뒷면 정렬은
도면상 맞는 것과 프린터에서 맞는 게 다르다. 한 장만 먼저 뽑아 잘라보고 슬리브에 넣어보는
게 순서다.

**A4와 여백은 바꾸지 않는다.** 여백 9mm는 포커 카드 3열(190.5mm)이 들어가는 상한
9.75mm에서 나온 값이다. 올리면 장당 9장이 8장이 된다.
