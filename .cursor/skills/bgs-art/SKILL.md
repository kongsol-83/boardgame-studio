# 아트 생성

`projects/<slug>/art/` 에 에셋을 만든다. 아트 부서 5명을 조율한다.

## 시작하기 전에

**룰이 굳었는지 확인한다.** 룰이 흔들리는 동안 카드 아트를 뽑으면 카드가 바뀔 때마다
다시 뽑아야 한다. `/bgs-pnp` 는 아트 없이도 프로토타입을 내주므로, 도형 버전으로
손 플레이테스트를 돌려 룰을 먼저 굳히는 게 순서다.

룰이 아직 흔들린다면 그 사실을 알리고, 그래도 진행할지 사용자에게 묻는다.

**공모전에 낼 거면 요강의 AI 아트 규정을 먼저 확인한다.** 요강에 따라 AI 생성 이미지를
금지하거나 명시를 요구하는 경우가 있다. 프로토타입 플레이테스트용으로는 문제없지만
제출 패키지에 넣기 전에 확인이 필요하다. **첫 실행 때 이걸 한 번 짚고 넘어간다.**

## 진행

```
- [ ] 1. 아트 바이블을 쓴다
- [ ] 2. 앵커를 뽑는다
- [ ] 3. 승인받는다
- [ ] 4. 프롬프트를 채운다
- [ ] 5. 한 컴포넌트를 뽑고 확인한다
- [ ] 6. 나머지를 뽑는다
- [ ] 7. 정보 설계를 점검한다
```

### 1. 아트 바이블

`bgs-art-director` 에게 맡긴다. `art/art-style.md` 를 쓴다.

이 문서가 모든 프롬프트의 공통 접두사가 되므로 여기가 흐릿하면 뽑히는 그림도 흐릿해진다.
매체, 팔레트, 조명, 구도, 선, 금지를 채우되 **각 항목에 "무엇을 쓰지 않는가"를 같이
적는다.** 금지가 없으면 모델이 평균적인 그림으로 수렴한다.

### 2. 앵커

```bash
node tools/art.mjs anchor <slug> --set character --subject "..." --n 3
```

앵커 세트는 `spec.json` 의 `anchor_sets` 에 선언된 것들이다. 인물·생물 계열은
`bgs-char-illustrator`, 환경·사물 계열은 `bgs-scene-illustrator` 가 소재를 고른다.

**가장 전형적인 것으로 뽑는다.** 특이한 걸 앵커로 삼으면 나머지가 그 특이함을 따라간다.

### 3. 승인

```bash
node tools/art.mjs approve <slug> --set character --pick 2
```

`bgs-art-director` 가 고른다. **승인 전에는 도구가 배치 생성을 거부한다.** 앵커가 틀린
채로 60장을 돌리면 돈과 시간을 그대로 버리기 때문이다.

셋 다 아니면 승인하지 말고 바이블을 고쳐서 다시 뽑는다. 앵커 몇 장 더 뽑는 비용은
전체 재생성에 비하면 아무것도 아니다.

### 4. 프롬프트

컴포넌트 CSV에 `art_prompt` 컬럼을 채운다. **소재만 적는다.** 화풍은 아트 바이블이,
프레이밍 제약(안전 여백, 글자 금지, 명도 하한, 유효 DPI)은 도구가 붙인다.

카드 효과와 그림이 이어지게 한다. 플레이어가 그림만 보고 무슨 카드인지 짐작할 수 있으면
좋은 아트다.

### 5. 한 컴포넌트 먼저

```bash
node tools/art.mjs estimate <slug>
node tools/art.mjs gen <slug> --component action-card
```

`bgs-art-lead` 가 실행한다. **전체를 한 번에 돌리지 않는다.** 60장을 다 뽑았는데 화풍이
틀렸으면 전부 다시 뽑아야 한다. 한 종류를 끝내고 디렉터에게 확인받은 뒤 넘어간다.

품질 기본은 `low` 다. 세로형 카드 기준 low에서 high가 **33배 차이**이고, 룰이 아직
흔들리는 동안에는 방향만 보면 된다.

### 6. 나머지

디렉터가 드리프트를 판정해 **재작업 ID 목록**을 내면 리드가 한 번에 묶어 돌린다.

```bash
node tools/art.mjs gen <slug> --only AC03,AC07,AC11 --force
```

절반 이상이 안 맞으면 개별 재생성이 아니라 앵커나 바이블을 다시 본다.

### 7. 정보 설계

`bgs-graphic-designer` 에게 맡긴다. 그림이 다 나온 뒤에 본다.

- 아트 위에 글자를 얹어 대비가 무너지지는 않는가
- 아이콘이 모양으로 구분되는가 (색만으로 구분하면 색약인 사람에게는 정보가 없다)
- 손패를 부채꼴로 쥐었을 때 위쪽만 보고 구분되는가

## 파일 규칙

`art.mjs` 가 `art/<comp-id>/<row-id>.png` 로 저장하고, `pnp.mjs` 가 같은 규칙으로
찾는다. **`art_file` 컬럼을 손으로 채울 필요가 없다.** 다른 파일을 쓰고 싶을 때만 적는다.

공통 뒷면은 `art/<comp-id>-back.png` 에 둔다.

## 다음

```bash
node tools/pnp.mjs <slug>
```

아트를 얹어 다시 렌더한다. **한 장 뽑아서 잘라본다.** 화면에서 괜찮아 보이는 것과 A4에
뽑아 자른 것은 다르다.

## 주의

**`gpt-image-2` 는 투명 배경을 지원하지 않는다.** 카드는 풀블리드라 상관없지만, 배경을
따야 하는 토큰이나 미플이 필요하면 `studio.config.json` 의 `models.image` 를
`gpt-image-1.5` 로 내리거나 후처리해야 한다.

**규격을 바꾸면 이미 뽑은 그림의 비율이 안 맞는다.** `spec.json` 의 `size_mm` 을 바꾸기
전에 그 컴포넌트에 몇 장을 뽑아뒀는지 확인한다. 돈이 드는 결정이다.
