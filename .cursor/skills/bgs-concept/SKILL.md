# 컨셉 확정

아이디어를 **핵심 동사 한 문장**으로 낮추고 기본 스펙을 못 박는다. 산출물은
`projects/<slug>/concept.md` 하나다.

이 단계가 흐릿하면 이후 전부가 흔들린다. 메커니즘을 고를 기준도, 검토할 기준도
여기서 나온다. 반대로 여기가 선명하면 나머지는 그것에 맞추면 된다.

## 진행

```
- [ ] 1. 아이디어에서 핵심 동사를 뽑는다
- [ ] 2. 그 동사가 만들어내는 순간을 확인한다
- [ ] 3. 기본 스펙을 확정한다
- [ ] 4. 무엇을 안 할지 정한다
- [ ] 5. concept.md 를 쓴다
```

각 단계에서 **먼저 묻고, 선택지를 주고, 사용자가 고른다.** 대신 정하지 않는다.

문서는 `studio.config.json` 의 `language` 로 쓴다. 확인은 `node tools/config.mjs` 로 한다.
슬러그와 파일명은 언어와 무관하게 영문 소문자 하이픈을 쓴다.

### 1. 핵심 동사

"이 게임에서 플레이어가 반복하게 될 행동이 무엇인가?"를 묻는다.

동사여야 한다. 명사나 소재는 핵심 동사가 아니다. "1차 대전 항공전"은 소재고,
"상대의 다음 기동을 읽고 먼저 자리를 잡는다"가 동사다.

아이디어가 소재나 세계관으로만 왔다면 **그대로 진행하지 말고** 동사 후보를 2~4개
제시해서 고르게 한다. 같은 소재로도 전혀 다른 게임이 나오기 때문이다.

한 문장으로 쓴다. 두 문장이 되면 아직 더 좁혀야 한다.

### 2. 그 동사가 만드는 순간

핵심 동사가 정해지면 그것이 테이블에서 어떤 장면을 만드는지 확인한다.

- 플레이어가 **고민하게 되는** 순간이 어디인가
- **탄성이 나오는** 순간이 언제인가
- 이겼을 때 **무엇 덕분에** 이겼다고 느끼는가

이게 안 그려지면 동사가 아직 추상적이다. 1로 돌아간다.

### 3. 기본 스펙

각각 선택지를 주고 고르게 한다. 근거를 같이 말한다.

- **인원** — 최소, 최대, 그리고 베스트 인원. 2인이 되는지는 특히 중요하다
- **플레이타임** — 목표 분. 공모전 심사에서 시연 시간은 현실적인 제약이다
- **무게** — BGG 기준 1~5. 이후 유사작 검색의 필터가 된다
- **타깃** — 누구와 하는 게임인가. 가족, 게이머, 커플, 입문자

### 4. 무엇을 안 할지

**이 단계를 건너뛰지 않는다.** 범위를 미리 닫아두지 않으면 나중에 전부 다 하려다
아무것도 완성 못 한다.

- 이 게임에 들어가지 않을 것 (확장, 캠페인, 레거시, 비대칭 진영 등)
- 목표 컴포넌트 규모 (카드 몇 종, 보드 유무). 대략이라도 정해둔다

### 5. 문서

`projects/<slug>/concept.md` 를 쓴다. 슬러그는 소문자 하이픈이다.
초안을 보여주고 승인받은 뒤 파일에 쓴다.

```markdown
# <제목>

## 핵심 동사
<한 문장>

## 이 동사가 만드는 순간
- 고민: ...
- 탄성: ...
- 승리감: ...

## 기본 스펙
| 항목 | 값 |
| --- | --- |
| 인원 | 2-4인 (베스트 3인) |
| 플레이타임 | 45분 |
| 무게 | 2.5 |
| 타깃 | ... |

## 안 하는 것
- ...

## 목표 컴포넌트 규모
- ...
```

## 주의

**소재보다 동사를 앞에 둔다.** 세계관과 설정은 매력적이지만, 실제 플레이 장면과
연결되지 않으면 아직 설계가 아니다. 고증이나 테마 디테일이 길게 나오면 "그게 플레이어의
어떤 행동으로 나타나는가"를 되묻는다.

**핵심 동사가 안 정해졌으면 다음으로 넘어가지 않는다.** 이후 모든 검토가 이 한 문장을
기준으로 이뤄진다. 여기가 비면 `bgs-mechanism-critic` 이 판단할 근거가 없어진다.
